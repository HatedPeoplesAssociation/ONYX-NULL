# ONYX-NULL Media Policy

## Purpose

This document defines how ONYX-NULL visual media should be created, stored, labeled, modified, and published.

---

# Core Principles

ONYX-NULL media should be:

```text
ACCURATE
   +
TRACEABLE
   +
ACCESSIBLE
   +
REPRODUCIBLE
   +
HONEST
```

---

# Media Categories

Use one of the following categories:

```text
BRANDING

DIAGRAM

PHOTOGRAPH

RENDER

TEST EVIDENCE

DOCUMENTATION
```

---

# Authenticity

Media must not imply a development status that has not been achieved.

Examples:

A CAD render must not be presented as a finished product.

A mockup must not be described as functioning hardware.

A stock image must not be presented as ONYX-NULL hardware.

---

# Labels

Use clear labels when appropriate:

```text
CONCEPT

EARLY DESIGN

RENDER

BENCH PROTOTYPE

ENGINEERING SAMPLE

TEST SETUP
```

---

# Technical Evidence

Images used as test evidence should record:

```text
Prototype:

Hardware Revision:

Test ID:

Date:

Description:
```

where practical.

---

# Redaction

Sensitive information may be redacted.

Examples:

- credentials
- MAC addresses
- serial numbers
- public IP addresses
- location information
- personal information

Redaction should not remove information necessary to evaluate the technical claim.

---

# EXIF and Metadata

Before public release, inspect image metadata.

Potentially sensitive fields include:

```text
GPS coordinates

Capture time

Device model

Software

Author

Comments
```

---

# Screenshots

Screenshots should be reviewed for:

- usernames
- hostnames
- notifications
- browser tabs
- credentials
- private repository names
- personal files
- network addresses

---

# Test Equipment

Photographs of test setups should identify important equipment where relevant.

Example:

```text
Multimeter:
<model>

Power Supply:
<model>

Logic Analyzer:
<model>
```

---

# Image Editing

Technical media may be edited for clarity.

Allowed examples:

- crop
- rotate
- brightness adjustment
- annotations
- arrows
- labels
- redactions

Do not modify technical evidence in a way that changes the underlying result.

---

# Source Preservation

Keep the original image where practical.

Example:

```text
ONX-P0-test-original.jpg

ONX-P0-test-annotated.png
```

---

# Generated Images

AI-generated or conceptual imagery may be used for branding or design exploration.

It must not be presented as actual hardware evidence.

Label it clearly when ambiguity is possible.

---

# Licensing

Media licensing should be documented.

Original ONYX-NULL media may use a project-selected documentation or media license.

Third-party assets retain their original license requirements.

---

# Current Status

This policy applies to all future ONYX-NULL public media.
