# ONYX-NULL Photographs

This directory contains photographs documenting ONYX-NULL development.

Photographs should preserve the physical history of the project.

---

# Purpose

Photographs may document:

- prototype builds
- hardware revisions
- PCB revisions
- wiring
- test setups
- assembly
- failures
- rework
- enclosure development
- finished milestones

---

# Suggested Structure

```text
photos/
├── P0/
├── P1/
├── mainboard/
├── testing/
├── assembly/
└── failures/
```

---

Preferred:

ONX-P0-bench-front-2026-08-16.jpg

ONX-P0-audio-test-2026-08-16.jpg

ONX-M1-REV-A-top.jpg

ONX-M1-REV-A-bottom.jpg

# Failure Documentation

Photograph failures when useful.

Examples:

- damaged connector
- PCB rework
- thermal damage
- mechanical interference
- broken FPC
- incorrect footprint
- wiring error

Failure documentation should be preserved because it may help future builders avoid repeating the same mistake.

---

# Test Evidence

Test photographs should identify relevant equipment and measurement context.

Example:

```text
HW-004
Wi-Fi Kill-Switch Test

Measured Rail:
3V3_WIFI

Expected:
0 V

Observed:
0.01 V
```

---

# Privacy Review

Before publishing, inspect photographs for:

- GPS metadata
- reflections
- screens
- notifications
- labels
- addresses
- serial numbers
- passwords
- network information
- background documents

---

# Originals

Keep original photographs where practical.

Annotated versions should use separate filenames.

Example:

```text
ONX-P0-power-test-original.jpg

ONX-P0-power-test-annotated.png
```

---

# Editing

Basic edits are acceptable:

- crop
- rotate
- exposure
- color correction
- annotation
- redaction

Do not alter evidence in a misleading way.

---

# Resolution

Keep sufficient resolution to inspect technical details.

Avoid unnecessarily massive files where a smaller version preserves all useful information.

---
